# 意群稳定与本地 VAD：实验方案

状态：研究中的 Draft PR。目标是减少 MT 预览回改，同时保持正确性和有界延迟。
本轮实验不改变默认字幕行为；实际效果必须由同输入对照决定。

首轮离线模型、参数敏感性与候选状态机结果见
[研究报告](../development/2026-10-13-mt-stability-research.md)。

## 选型

- [Silero VAD](https://github.com/snakers4/silero-vad)：小型语音活动检测模型，
  用于判断语音和停顿，不负责翻译，也不理解意群。
- [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)：支持本地 ASR、VAD 等的
  运行框架，已经支持 Silero。二者不是两个可直接比较的翻译模型。
- 优先比较相同 Silero 权重在直接 ONNX Runtime 和 sherpa-onnx 中的实际
  运行成本、分段结果及集成成本。模型、运行库和最终安装包增量分别记录。
  不能只凭模型文件大小判断自带成本，也不能把 Python wheel 大小当安装包增量。

## Mimi 当前边界

基线 `5257f7e6`：`ASRDraftCommitter` 保留完整可替换原文；预览通道重译
完整草稿，包含未完成尾部。现有 pacer 已约束请求间隔、同长度回改和限流。
只有服务 final 和有界的会话结束 fallback 进入最终队列。减少请求次数
与减少屏幕上已经显示文字的回改不是同一个指标。

## 要验证的方案

1. 基线：完整草稿重译，沿用已有有界调度。
2. 只等停顿：用 VAD 结束信号提交整段。观察句中停顿和连续长句的误切、等待。
3. 稳定意群：原文稳定性、完整边界和停顿联合选择候选；已接纳片段保持，
   只翻译未确认尾部。强制等待上限只能触发可替换预览，不能伪造 final。

研究候选需要证明以下规则后，才进入 shared runtime 的默认路径：

- 服务 final 保持权威；本地停顿不能变成持久历史，也不能冻结错误原文。
- ASR 修正已稳定前缀时显式撤销对应预览；不拼接来自不同原文版本的译文。
- 英文缩写、小数、日语句尾否定、中文未完成分句和连续无标点语音保留反例。
- MT 必须使用相同模型、提示词、上下文预算和采样设置；不改官方协议提示词。
- 系统声音和麦克风各自持有模型状态、样本时钟、原文版本和队列。
- 不按 VAD 丢弃识别音频；停顿只是候选信号，不能影响识别服务的连续输入。
- clear、停止、重连、来源切换取消旧代次；迟到响应、失败、空结果不得推进边界。
- PCM、原文、译文和队列有固定上限，普通诊断只保留数字与状态。

## 验证与交付

离线模型实验使用显式输入文件、固定模型 SHA256、单线程和独立状态；
保存处理耗时、冷启动、边界时刻和模型大小，不保存输入正文。准备数字静音、
有声无语音和合成语音对照，再复用有使用依据的真人音频。

策略回放记录首次可读译文、最终延迟、回改字数、回改次数、MT 请求次数、
错误前缀撤销和漏句。合成对照只能证明策略行为，不代表翻译质量提升。
语义正确性要由相同真人样本及独立参考评审；模型速度不能代替该项。

生产接入应位于 `shared/mimi-runtime`／`shared/mimi-core`，桌面与 Android
共用实现，并补直接 Rust、真实 JNI 和各平台包验证。试验成功后再决定采用
ONNX Runtime、sherpa-onnx 或其他经过等价性验证的推理方式。
