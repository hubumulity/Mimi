# 惨叫/喘息退化语句过滤

设置 → 字幕新增开关「过滤惨叫/喘息」，默认关。开启后，人物惨叫、喘息
被识别成的一长串语气词不再显示；正常说话不受影响。

## 判定：整句退化才删

不是「含语气词就删」，而是「整句退化」：去掉标点、空白和拉长音
（——、～、ー）后，剩下的内容全部是语气词，且达到 3 个单位才算退化。

- 删：啊啊啊、嗯嗯嗯嗯、啊——啊——啊、oh oh oh、um um um、あああ、아아아。
- 不删：单个啊/哦（可能是回应）、啊啊（未达到连续长度）、嗯，我觉得……
  （句中有实词）、啊啊啊救命（句中有实词）、哈哈哈（笑声不属于语气词表）。

语气词表不区分源语言，用中日韩语气词字与英语语气词的并集：因为判定
要求整句全是语气词，真实句子几乎必然含有表外字符，所以并集不会误伤
实词。两端语气词串的修剪（啊啊啊救命 → 救命）本次不做，只做整句删。

哈、哼不在表中：前者保护整句笑声，后者可作有意义的鼻音回应。
如需覆盖被识别成哈哈哈的喘息，再把哈加入表中。

## 落点：共享核心的一个谓词

判定函数在 `shared/mimi-core/src/degenerate_utterance.rs`，
开关是 reducer 的 `filter_degenerate_utterances` 字段（默认 false，
`#[serde(default)]` 兼容旧状态）。所有表面共用这一个谓词：

- 确认成对时：`FinalPair`、`IdentifiedFinalPair`、`ConfirmedPair`、
  `TranslationFinal`、翻译终稿 `UtteranceText` 在 `apply` 入口直接返回，
  不产生行、显示对、历史与存档；`confirm_display_pair` 与
  `append_confirmed_history` 各有一道后备门。
- 实时预览时：`SourceDraft`、`TranslationDraft`、`SourceUtteranceDraft`、
  非终稿 `UtteranceText` 的退化文本置空行；退化的 `PreviewPair` 清空预览
  状态。惨叫进行中悬浮窗不闪那一串啊啊啊，恢复实词后预览自动回来。
- 终稿源文行退化时同样置空，避免原文/双语模式下尾行短暂漏出。

因此显示、聚合历史、存档（保存文件）与导出同步干净，无需各端再实现。
翻译提示词与语气词对照表是服务商原样资产，本功能是文本后处理，不动它们。

## 偏好贯通

桌面：`Preferences.filter_degenerate_utterances` → 快照/草稿 →
设置开关（八语言文案）→ 保存时经 session manager 立即作用于运行中会话，
新会话启动时从偏好重设。运行期控制器向双路 lane 转发。

Android：共享核心与 bridge 已支持同一开关（`filter_degenerate_utterances`
操作），但 Captions 暂不暴露开关，故默认关；差异记入 platform-parity。

## 验收

- 核心：退化判定分语言、阈值、标点与拉长音、笑声保留；开关开时终稿、
  草稿、预览、存档四处皆无退化句，开关关时旧行为不变；旧状态缺字段时
  默认为关；会话边界不重置开关。
- 前端：合并默认关、无关保存保留选择、开关保存往返。
- 仍需用户在 Mac 上实测：真实惨叫音频下悬浮窗是否全程无退化句，
  以及恢复说话后首句是否正常出现。
